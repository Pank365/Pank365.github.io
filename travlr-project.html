Project Overview

Travlr Getaways is a full-stack travel application that allows customers to browse vacation packages while authorized administrators manage trip information through a secure single-page application.

The project demonstrates client-server architecture, responsive interface design, RESTful API development, database integration, authentication, secured updates, testing, and technical documentation.

System Architecture

Multi-tier architecture showing communication between the Angular client, Express and Node.js server, REST API, and MongoDB database.

Application Interface

Angular single-page application displaying available travel packages retrieved from the backend API and MongoDB database.

Core Features

Trip Browsing

Customers can view available travel packages through a clean, responsive interface that presents trip images, locations, descriptions, and pricing.

Administrator Management

Authorized administrators can add and edit trip data through protected application features connected to the REST API.

Persistent Data

MongoDB stores trip records and supports reliable retrieval and updates across the application.

Authentication and Security

The application uses JWT authentication to protect administrative features and secured API endpoints. After a successful login, the frontend stores the token and includes it with protected requests.

Unauthorized users cannot access administrative controls, and invalid or missing authentication tokens result in rejected requests.

REST API Endpoints

GET

/api/trips

Retrieves the available trip records.

POST

/api/login

Authenticates a user and returns a JWT.

POST

/api/register

Creates a new member account.

POST

/api/trips

Creates a new trip through an authenticated request.

PUT

/api/trips/:tripId

Updates an existing trip record.

DELETE

/api/trips/:tripId

Removes a trip through an authorized administrative request.

Database Integration

MongoDB serves as the application's persistent data layer. The Express backend uses Mongoose models to communicate with the database and perform CRUD operations on trip records.

This separation keeps database logic out of the interface and supports a more maintainable application architecture.

Testing and Validation

I tested both public and protected application behavior, including trip retrieval, user authentication, authenticated trip updates, database persistence, and unauthorized request handling.

  • Confirmed that GET requests loaded trip data into the SPA.
  • Verified that successful login returned and stored a JWT.
  • Tested protected PUT requests with valid authorization headers.
  • Confirmed that invalid or missing tokens returned authorization errors.
  • Verified that successful updates were written to MongoDB.

Engineering Challenges

Client-Server Communication

Connecting the Angular frontend to the Express API required careful attention to routing, request formatting, response handling, and error diagnosis.

Authentication Flow

Implementing JWT authentication required coordinating login, token storage, frontend state, protected routes, and authorization headers.

Database Updates

Testing secured updates required confirming that the request passed through the frontend service, interceptor, Express middleware, controller, model, and MongoDB database.

Lessons Learned

This project strengthened my understanding of how a modern full-stack application operates as a complete system. I learned that the quality of the application depends not only on individual technologies, but on how clearly and reliably each component communicates with the others.

The project also reinforced the importance of security, negative testing, modular design, clear documentation, and persistent troubleshooting when multiple application layers must work together.
